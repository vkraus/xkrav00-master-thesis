\chapter{Data Model Design}
\label{ch:model-design}

Framework design is conceptual, i.e. solution-agnostic - can be implemented on any data platform (dbx, snowflake, fabric, google bigquery) - use generic concepts and open industry standards instead of assuming proprietary technology

Needs to support both OLTP/OLAP use cases

Silver layer : Entities (dimensions), Findings (facts), Relationships (entity-to-entity, finding-to-entity)

\section{Architecture Context}

It will be used to pull data from data sources (those are naturally out of scope)

It needs to be ready to support an application security management dashboard with a combination of OLTP and OLAP use cases (dashboard application also out of scope).
