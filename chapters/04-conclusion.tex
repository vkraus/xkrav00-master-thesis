\section*{Thesis Outcomes and Contributions}
\addcontentsline{toc}{section}{\protect\numberline{}Thesis Outcomes and Contributions}

This thesis delivers the three contributions announced in the abstract. The first is a \textbf{requirements specification} for an application security data platform, grounded in the \hyperref[ch:analysis]{Analysis} chapter. The full specification is published on the documentation site and attached as \texttt{appsec-mvp-docs.zip}, because it is too long for an appendix. The second is a \textbf{reusable and extensible framework} (\hyperref[ch:framework]{Framework chapter}) covering reference architecture, data model, and the medallion based pipeline~\parencite{Strengholt2025} from source records to consumption. The third is a \textbf{Databricks MVP reference implementation} (\hyperref[ch:implementation]{MVP Implementation chapter}) with generated connector modules for nine selected data sources, explicit evidence levels in the \hyperref[sec:impl-results]{Aggregate Results section}, and the implementation archive attached as \texttt{appsec-mvp.zip}.

In design science terms, the framework is the artifact~\parencite{Hevner2004, Peffers2007}. The \hyperref[ch:analysis]{Analysis} chapter establishes problem relevance, and the \hyperref[ch:implementation]{MVP Implementation} chapter demonstrates the artifact through the \gls{mvp}. Evaluation comes from requirement linked tests, the traceability matrix, and the \gls{ai} instantiability assessment. Two limits remain: the \gls{ai} evaluation criterion was finalized after early reviewer cycles, and design alternatives are recorded only in the iteration summary.

The framework is \textbf{reusable} because the \hyperref[ch:implementation]{MVP Implementation} chapter introduced no new connector level design decisions beyond which sources to onboard. It is \textbf{extensible} because onboarding a new source reduces to the five step procedure of the \hyperref[sec:impl-methodology]{Methodology section}: category resolution, module instantiation, mapping specification, layered testing, and skill chain pass with reviewer supervision. ServiceNow, GitHub, SonarQube, and \gls{owasp} \gls{zap} are concrete examples of the same contract supporting different integration patterns.

\section*{Evaluation of AI Instantiability}
\label{sec:ai-eval}
\addcontentsline{toc}{section}{\protect\numberline{}Evaluation of AI Instantiability}

The \hyperref[ch:framework]{Framework} chapter aimed the framework outputs at an \gls{ai} coding agent. The original target was fully autonomous generation from the agent \href{https://vkraus.github.io/appsec-mvp/connectors/scm/skills/}{skill catalog}. The \gls{mvp} was produced by invocations of that catalog under reviewer subagent supervision (Subagent-Driven Development).

\subsection*{Acceptance criterion}

A correction counts as a \textbf{framework gap} when extending the specification (schema pattern, connector contract from the \hyperref[sec:connector-contract]{Connector Contract section}, or declarative artifact) would have produced the right output on first pass and the extension would generalize. Corrections tracing to \textbf{source specific issues} or \textbf{environment setup} (setup, authentication, infrastructure) do not count against the framework.

\subsection*{Empirical outcome}

The four-skill chain ran across all nine source specifications, producing connector modules for each source and validation evidence. The \hyperref[sec:iteration-summary]{Iteration Summary section} enumerates the defects the reviewer cycle caught: a layering boundary (framework gap), schema drift between \gls{sql} \gls{ddl} and PySpark types (framework gap), a secret scope mismatch (environment setup), worktree pollution (environment setup), a cron schedule collision (source specific issue), and IRSA OIDC trust policy gaps (environment setup). Two of six classify as framework gaps. Evidence lives in the \href{https://vkraus.github.io/appsec-mvp/}{documentation site}.

\subsection*{Claim defended}

The defended claim is limited to supervised connector generation. The skill catalog produced connector artifacts for nine sources, and reviewer subagents caught the defect classes listed in the \hyperref[sec:iteration-summary]{Iteration Summary section}. The \hyperref[sec:impl-results]{Aggregate Results section} separates generated artifacts, live source exercise, and Spark wrapper completeness.

This does not prove autonomous generation. The platform layer and analytics layer were hand written. The evidence comes from one framework user, the author, acting as both implementer and reviewer of the evaluation, without inter rater reliability or an independent grader. A controlled study with multiple framework users would be needed to measure autonomy. The open schema drift gap and the remaining implementation items also have to be closed before a stronger autonomy claim can be made.

\section*{Limitations}
\label{sec:conclusion-limitations}
\addcontentsline{toc}{section}{\protect\numberline{}Limitations}

The \gls{mvp} is a working reference rather than a production ready integration. It is \textbf{platform specific}: it runs on Databricks over \gls{aws} object storage, the only combination exercised end to end. \textbf{Live tenant exercise} is partial: of the nine connectors, ServiceNow, GitHub, SonarQube, Semgrep, and \gls{owasp} \gls{zap} have been exercised against live source systems during the construction of this thesis. The remaining four (GitLab, Dependency-Track, TruffleHog, \gls{aws} \gls{waf}) pass their unit tests against fixtures but have not been exercised against a live tenant. The connector contract in the \hyperref[sec:connector-framework]{Connector Framework section} is written to be cloud and platform agnostic in principle, but it has not been ported to Snowflake, Microsoft Fabric, or an on premises platform, so the portability claim rests on contract design alone, with no second demonstrated implementation.

\textbf{Reproducibility} requires a Databricks workspace with Unity Catalog, an \gls{aws} account with an S3 bucket and federated credentials, a Lakeflow Connect entitlement, a ServiceNow developer instance, and a GitHub Personal Access Token (\gls{pat}). The Declarative Automation Bundle, formerly Databricks Asset Bundle~\parencite{DatabricksDAB2026}, deploys every workspace resource the bundle format covers natively. The post deploy shell script \inlinecode{src/platform/scripts/bootstrap.sh} creates the secret scope container, Unity Catalog storage credential, and Unity Catalog external location. Per connector Terraform modules under \inlinecode{src/connectors/<source>/runtime/} provision source side cloud infrastructure. The archives attached to this thesis, \inlinecode{appsec-mvp.zip} and \inlinecode{appsec-mvp-docs.zip}, cannot reproduce the build without these entitlements.

Several \textbf{open implementation items} remain, but they are narrower than the framework gaps before the redesign summarized in the \hyperref[sec:iteration-summary]{Iteration Summary section}. Connector population of \inlinecode{silver.repositories} is partial: GitHub writes the standard narrow repository fields, while wider target fields and GitLab parity remain future work. Application attribution has one implemented path, not the full CMDB relationship story. \inlinecode{silver.app\_repo\_mapping} is populated by a platform linker over \inlinecode{silver.applications} and \inlinecode{silver.repositories}, using application codes embedded in repository names. Parallel CMDB relationship paths through \inlinecode{cmdb\_rel\_ci}, explicit repository link columns, and fuller connector side repository writers remain pending. Several Spark connector wrappers currently return empty Silver DataFrames with target schemas while their mapping helpers at row level are tested. SonarQube and \gls{owasp} \gls{zap} have Spark transforms that emit rows. Some notebook entry wrappers generated by skills remain placeholders. Dependency-Track live dltool execution and the \gls{aws} \gls{waf} boto3 sampled request fallback remain deferred, while the WAF log stream path is the preferred design. Inherited error handling sharp edges remain in \inlinecode{bootstrap.sh} and the ServiceNow Terraform runtime, both flagged for hardening.

The analytics and serving layer is implemented as evidence for the thesis rather than a production service. It includes five Gold datasets, one Gold view, two Online Table resources, suppression rules, and a Databricks App. The tests are backed by fixtures, mocked, or marked for Spark/live execution as appropriate. The thesis does not claim production deployment, measured serving latency, or trained \gls{ml} models.

The \textbf{variation} of the selected sources is biased toward \gls{rest} \gls{json} \glspl{api} with token authentication (five of the nine: GitHub, GitLab, ServiceNow, SonarQube, Dependency-Track). \gls{aws} \gls{waf} consumes a log stream from Kinesis Data Firehose to S3 with SigV4 service credentials rather than a bearer token, \gls{owasp} \gls{zap} follows an artifact pattern, and the two file based sources (Semgrep, TruffleHog) deliver via S3 instead of an interactive \gls{api}. Source categories not demonstrated include SOAP, gRPC, syslog, Kafka event streams, binary telemetry, and push only webhook native sources. The contract is written to accommodate these, but evidence is absent on a category by category basis.

\section*{Future Work}
\label{sec:future-work}
\addcontentsline{toc}{section}{\protect\numberline{}Future Work}

\subsection*{Implementation backlog}

\textbf{Closing the remaining framework gap.} The layering boundary gap was closed by the structural redesign. The schema drift gap remains open. A single source of truth for silver schemas resolving the drift between \gls{sql} \gls{ddl} and PySpark \inlinecode{StructType} definitions is the precondition for any stronger \gls{ai} autonomy claim.

\textbf{Completing the declarative mapping applicator and Spark wrapper wiring.} The \hyperref[sec:transformation-patterns]{Transformation Patterns section} treats \inlinecode{mapping.yml} as the authoritative specification consumed by a generic applicator, but the \gls{mvp} applies mappings through Python helpers and Spark code for each source. Completing the applicator and replacing the remaining wrappers with Spark transforms that emit rows would move new source onboarding closer to configuration than code.

\textbf{Realizing the remaining prescribed silver tables.} The framework prescribes 15 silver tables (\hyperref[sec:entity-model]{Entity Model section}). The \gls{mvp} realizes the core subset \inlinecode{applications}, \inlinecode{repositories}, \inlinecode{findings}, \inlinecode{finding\_location}, \inlinecode{hwm}, \inlinecode{app\_repo\_mapping}, and \inlinecode{suppression\_rules}. Future iterations should add the remaining entity tables (\inlinecode{teams}, \inlinecode{commits}, \inlinecode{pull\_requests}, \inlinecode{pipeline\_runs}, \inlinecode{dependencies}, \inlinecode{branch\_policies}), the reference tables (\inlinecode{vulnerabilities} from the \gls{nvd}, \inlinecode{epss\_scores}, \inlinecode{kev\_entries}), and the remaining relationship table \inlinecode{finding\_cve\_mapping}. Cross tool overlap is currently computed in Gold rather than stored in a separate \inlinecode{dedup\_links} table. Adding a persisted dedup relationship remains a future extension.

\textbf{Finishing job orchestration and bootstrap hardening.} Some notebook wrappers generated by skills still need full job orchestration, and the remaining Spark wrappers need implementation. The bootstrap script and ServiceNow runtime need the hardening pass named in the \hyperref[sec:conclusion-limitations]{Limitations section}.

\textbf{Live analytics evidence and downstream triage.} The rule based Gold layer and Databricks App now exist, so the next step is to run them against live data from multiple sources, measure serving latency, and connect them to downstream triage workflows.

\subsection*{Research extensions}

\textbf{Replication of \gls{ai} instantiability.} The evaluation in this thesis used one framework user, the author, and reviewer subagent cycles. A controlled study with several framework users, a fixed source onboarding task, and independent grading would measure how well the skill chain transfers beyond the author and how far the framework remains from autonomous connector generation.

\textbf{Large Language Model assisted triage and correlation.} The Gold layer provides application risk posture, overlap, coverage, and remediation metrics. Large Language Model assisted triage and correlation over these tables is a natural extension and would exercise the data model of the \hyperref[sec:data-model]{Data Model section} in the direction it was designed for.
