\chapter{Generative AI Use Disclosure}
\label{app:genai}

This appendix expands the Declaration on the Use of Artificial Intelligence from the front matter of this thesis. The five sections below disclose each use in the same order as the front matter declaration. The central use is the \gls{ai} assisted construction of the reference implementation (\autoref{ch:implementation}), which is evaluated in \autoref{sec:ai-eval} rather than treated as incidental assistance.

The grammar and language style assistance described in the first section below used the Overleaf \gls{ai} assistant on the thesis manuscript~\parencite{Overleaf2026AIAssistant}. All other \gls{ai} assistance reported in this appendix used Claude models (Anthropic) accessed through the Claude Code \gls{cli}~\parencite{Anthropic2026ClaudeCode}, with model versions spanning Claude Opus~4.5 through Claude Opus~4.7 over the drafting period of the thesis~\parencite{Anthropic2025ClaudeOpus45, Anthropic2026ClaudeOpus46, Anthropic2026ClaudeOpus47}.

\section{Text Editing}

\Gls{ai} assistance feature in Overleaf online editor was used for grammar checking, style refinement, synonym replacement, sentence rephrasing, and other editing of the content I originally authored~\parencite{Overleaf2026AIAssistant}. I relied on the assistant throughout my drafts to identify errors, tighten phrasing, and highlight inconsistencies. I accepted, rejected, or revised the suggestions. I did not rely on any \gls{ai} assistant to autonomously generate thesis content. I wrote all new text material in the Overleaf editor, and only afterward revised it with \Gls{ai} support.

Several review cycles were carried out across the entire thesis using the Claude Code tool with Claude Opus models to condense it to its target length~\parencite{Anthropic2026ClaudeCode, Anthropic2025ClaudeOpus45, Anthropic2026ClaudeOpus46, Anthropic2026ClaudeOpus47}. These iterations rephrased longer passages into more concise wording and relocated some details into the attached \gls{mvp} documentation, which contains the requirements specification and reference material per data source. The restructuring decisions were mine. The \gls{ai} assistant proposed cuts and rephrasing that I accepted, rejected, or revised.

The research question, chapter structure, major contributions, and central claims are all mine. Positioning against prior work (\autoref{sec:related-work}) and the conceptual domain model (\autoref{sec:data-entities}) were also authored by me. Literature selection is mine, Claude Code was used to generate most bibliography entries in LaTeX format~\parencite{Anthropic2026ClaudeCode}. Several entries point at vendor product pages and white papers (used as primary sources for product capabilities and feature claims) instead of peer reviewed literature. These are flagged inline with the specific claim each one supports.

\section{Images}

\Gls{ai} assistance was used to generate TikZ source for figures from my sketches and textual descriptions of the content and layout. I reviewed and revised the figures for correctness and readability.

\section{Source Code (\texttt{appsec-mvp.zip})}

The reference implementation in \autoref{ch:implementation} (attached to this thesis as \texttt{appsec-mvp.zip}) was built across three distinct \gls{ai} assisted workflows, all using Claude Code with Anthropic Claude Opus models~\parencite{Anthropic2026ClaudeCode, Anthropic2025ClaudeOpus45, Anthropic2026ClaudeOpus46, Anthropic2026ClaudeOpus47}.

The first workflow predates the public \texttt{appsec-mvp} repository. Four connectors (ServiceNow, GitHub, Semgrep, \gls{owasp} \gls{zap}) were manually coded by me during the analysis phase, with Claude Code used conversationally for boilerplate and refactoring~\parencite{Anthropic2026ClaudeCode}, and committed as the initial repository snapshot. They have since been re-emitted by the skill chain. The current connector modules in the repository are output of the chain for all nine connectors, with the evidence levels and remaining wrapper gaps stated in \autoref{sec:impl-results}.

The second workflow was the connector skill chain published in the documentation site (MVP Documentation section below). It ran across all nine selected source specifications, producing the connector artifact set for each source and validation evidence. Each pass wrote evidence rows to the \gls{mvp} documentation (an Implementation log entry and a Validation table keyed by requirement IDs).

The third workflow was the structural redesign that centered the implementation on Databricks, run on a separate branch and merged through pull request \#2. It applied the Subagent-Driven Development pattern from the Superpowers plugin for Claude Code (brainstorm, then spec, then plan, then execute) using artifacts under \texttt{docs/superpowers/\{specs,plans\}/} in the \texttt{appsec-mvp} repository~\parencite{Vincent2026Superpowers}. Each task was implemented by a fresh Opus subagent and then reviewed by a separate specification compliance subagent and a separate code quality subagent across two reviewer cycles~\parencite{Anthropic2026ClaudeCode, Anthropic2025ClaudeOpus45, Anthropic2026ClaudeOpus46, Anthropic2026ClaudeOpus47}. The reviewer cycles caught the defect classes recorded in \autoref{sec:iteration-summary}: a layering boundary, schema drift between \gls{sql} \gls{ddl} and PySpark types, a secret scope mismatch, worktree pollution, a cron schedule collision, and IRSA OIDC trust policy gaps. The same Subagent-Driven pattern with paired reviewers was also applied to skill chain runs in the second workflow.

This is my main \gls{ai} use. \autoref{sec:ai-eval} evaluates it. The four skills published on the \href{https://vkraus.github.io/appsec-mvp/platform/reference/connector-skills/}{documentation site} are \inlinecode{analyze-source}, \inlinecode{provision-source}, \inlinecode{generate-connector}, and \inlinecode{validate-implementation}. They are an \gls{ai} assisted companion to the requirements specification.

\section{MVP Documentation (\texttt{appsec-mvp-docs.zip})}

The \href{https://vkraus.github.io/appsec-mvp/}{\gls{mvp} documentation}, attached to this thesis as \texttt{appsec-mvp-docs.zip}, is \gls{ai} assisted content.

I authored the four skills on the \href{https://vkraus.github.io/appsec-mvp/platform/reference/connector-skills/}{skills page} in Claude Code, using the Anthropic skill writing skill~\parencite{Anthropic2026ClaudeCode, Anthropic2026SkillsBestPractices}. Each skill carries one \inlinecode{SKILL.md} for the role and one \inlinecode{references/<category>.md} for each application security category exercised by the \gls{mvp} (CMDB, SCM, SAST, SCA, Secrets, DAST, WAF), totaling 32 authored files across the four skills. Container scanning and \gls{iac} scanning are part of the framework finding categories enumerated at \autoref{sec:silver-findings-design} but are not exercised by any \gls{mvp} connector, so the skill catalog does not yet ship reference pages for them. The layout follows the published Anthropic recommendation for skills that span multiple variants, defended in the Extension Blueprint section of \autoref{ch:framework}~\parencite{Anthropic2026SkillsBestPractices}. I iterated each skill until it produced the intended output. The skill chain was then used to generate connector code for the reference implementation, as disclosed in the Source Code section above.
