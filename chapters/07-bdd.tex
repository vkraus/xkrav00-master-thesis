\subsubsection{REQ-ING-002: SonarQube Integration}
\label{req:ing-002}

\begin{tabular}{@{}ll}
\textbf{Priority:} & Must Have \\
\textbf{Status:} & Not Started \\
\end{tabular}

\vspace{0.5em}

\noindent\textbf{Description:}
The system shall retrieve security findings from SonarQube server via REST API. Connection requires server URL and authentication token. Retrieved findings include vulnerability type, severity, affected file path, line number, and remediation guidance.

\vspace{0.5em}

\noindent\textbf{Acceptance Criteria:}

\begin{lstlisting}[language=Gherkin]
Feature: SonarQube Integration

  Background:
    Given a SonarQube server at "https://sonar.example.com"
    And valid API token is configured

  Scenario: Retrieve project vulnerabilities
    Given project "my-application" exists in SonarQube
    When the ingestion pipeline executes
    Then all security hotspots and vulnerabilities are retrieved
    And findings are stored in bronze layer with source identifier "sonarqube"

  Scenario: Handle pagination
    Given project "large-application" has 5000 findings
    When the ingestion pipeline executes
    Then all pages are retrieved
    And 5000 findings are stored in bronze layer

  Scenario: Handle authentication failure
    Given invalid API token is configured
    When the ingestion pipeline executes
    Then pipeline logs authentication error
    And no partial data is written to bronze layer

  Scenario: Handle server unavailability
    Given SonarQube server is unreachable
    When the ingestion pipeline executes
    Then pipeline retries 3 times with exponential backoff
    And pipeline fails gracefully after retries exhausted
\end{lstlisting}
